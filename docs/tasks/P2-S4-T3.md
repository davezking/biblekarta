## Why this model / review tier
- **Model:** static routes from compiled data, plus correct meta tags.
- **Review:** `auto`.

## Context
- FR-10: every item has a shareable URL. Architecture §5: `/p/<slug>/`, `/e/<slug>/`, `/era/<slug>/`, with **no verse text in the HTML** (verses load only in the panel).
- Demo step 9: open `/p/ahab/` directly → the panel opens with the chart focused, and view-source shows Ahab's name and dates.
- The compiled data (`public/data/index.json` and the tiles, P2-S2-T3) is written before the pages build. Read it at build time instead of re-parsing `content/`.
- `viewstate.ts` (P2-S3-T6) builds the chart state (`sel`, `y`, `z`). The chart page reads the URL on load through `url-sync.ts`.
- `Base.astro` has a `head` slot for meta tags. OG **images** come in Phase 4 (P4-S2-T3). Here: the title, description, canonical URL and `og:*` text tags only.
- Production with no content must still build: no live eras means no item pages.
- P2-S4-T2 runs in parallel and doesn't touch the i18n files; this task adds the `page.*` keys.

## Do this
1. **`src/build/item-pages.ts`:** `loadItemPages()` reads the compiled index and tiles and returns the people, events and eras with their slug, names, formatted dates on both axes (`formatScholarly`/`formatTraditional`), refs (`formatRef`) and the chart state to open them (`serializeViewState` with `sel` and a zoom framing the item).
2. **`/p/[slug]`, `/e/[slug]`, `/era/[slug]`:** `getStaticPaths` from `loadItemPages()`. Each page renders:
   - **server-side HTML:** the title cartouche, the name (Amharic, with the English name small), both dates with their certainty, and the refs as text (book name, chapter, verse; no verse text);
   - the chart island, opened on that item with the panel open (the same behaviour as following the `/?…` URL);
   - meta tags: `<title>`, `description` (name + dates), canonical `https://biblekarta.com/<kind>/<slug>/`, `og:title`, `og:description`, `og:url`, `og:type`;
   - `<html lang="am">` and `lang="am"` on Amharic text.
3. An era page lists its people and events (as links to their pages), with its date range and certainty label.
4. **i18n:** add `page.*` keys (the page titles and description templates) in `am.json` and `en.json`.

## Acceptance criteria
- With the seed, `/p/ahab/` exists. Its HTML contains "አክዓብ" and "874–853 ዓ.ዓ." without JavaScript, and no verse text.
- Opening `/p/ahab/` in a browser shows the chart focused on Ahab with the panel open.
- Every person, event and live era in the seed has a page, and every page has unique `<title>`, `description` and canonical tags.
- A production build with no content builds no item pages and doesn't fail.

## Tests to write or update
- `item-pages.test.ts`: the page list from a fixture index and tiles, the formatted dates, the view state, no verse text in the output fields.
- Build-level check: render one page with Astro's container API, or assert on `dist/p/ahab/index.html` in the existing build test pattern.
