## Why this model / review tier
- **Model:** accessible interactive widgets (focus, keyboard, touch) with no UI library.
- **Review:** `auto`.

## Context
- `CLAUDE.md`: small typed components, no UI library, tokens only. Touch targets ≥ 44 px. Respect `prefers-reduced-motion`. Controls use `--font-ui` (Noto Sans Ethiopic).
- DR-11: on desktop (≥ 1024 px), selecting an item opens a side panel. DR-12: on mobile (< 1024 px), details open in a bottom sheet.
- The toolbar (Sprint 3) needs a button, a two-way switch (scholarly ↔ traditional) and a menu of checkboxes (lane toggles). The panel (Sprint 4) needs a chip (certainty), a disclosure ("እንዴት ታወቀ?") and the panel container.
- User-facing strings go in `src/i18n/*.json` (`createT` in `src/lib/i18n.ts`).

## Do this
1. **`src/components/ui/`:**
   - `Button`, `IconButton` (needs an `aria-label`)
   - `SegmentedSwitch` (two or more options, radio-group semantics, arrow keys)
   - `CheckboxMenu` (a button + popover with checkboxes; Esc closes it and focus returns to the button)
   - `Chip`, `Disclosure`, `Tooltip` (shown on hover, focus or long-press; dismissible with Esc)

   Each has a min 44×44 px hit area, tokens-only CSS and a visible focus ring.
2. **`src/components/panel/Panel.tsx`:** `{open, onClose, title, children}`.
   - **≥ 1024 px:** a side panel on the right that doesn't cover the chart's toolbar.
   - **< 1024 px:** a bottom sheet with a drag handle and two snap points (half, full). Swipe down closes it.
   - Both: `role="dialog"`, labelled by the title; Esc and a close button close it; focus moves in on open and returns to the opener on close.
   - The chart behind it stays usable on desktop, so it isn't modal there. The sheet traps focus while it's at full height.
   - Animations use the motion tokens, and none run under `prefers-reduced-motion`.
3. **i18n:** add `ui.close`, `ui.open_menu` and `panel.handle` (sheet-handle label) in `am.json` and `en.json`.

## Acceptance criteria
- Every interactive element is reachable and usable by keyboard alone, and has an accessible name.
- Every hit area is ≥ 44×44 px, checked in tests from the computed size.
- The panel picks side panel vs bottom sheet at the 1024 px breakpoint, and focus returns to the opener on close.
- No animation runs under `prefers-reduced-motion: reduce`.

## Tests to write or update
- One test file per primitive (happy-dom): roles and ARIA, keyboard behaviour, Esc, focus return.
- `Panel.test.tsx`: the layout choice by `matchMedia`, open/close, focus management, the snap points (simulated pointer events).

## How to test manually
1. On desktop, open a panel and press Tab → focus moves inside it; press Esc → it closes and focus goes back to the button.
2. On a phone (or 390 px emulation): open it → a bottom sheet; drag it up → full height; swipe down → it closes.
