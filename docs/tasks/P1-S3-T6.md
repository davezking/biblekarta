## Why this model / review tier
- **Model:** aggregation over existing files.
- **Review:** `auto`.

## Context
- The data: `work/flags.json`, `decisions/round-*.jsonl`, `rounds/samples/round-*.json`, the anchor-sheet results, the versification candidates and confirmations, and `scripture/books/*.json` (status) with `provenance/`.
- PRD v5.4 estimates 3–5 weeks of verification. You need to see the progress and what blocks each book.

## Do this
**`bk report`** writes `reports/verification.md` (committed) with:
1. **Overall:** books verified / 66 and verses in verified books / 31,102.
2. **Flagged verses by issue type:** total, applied, reviewed, pending, To do. This mirrors the workbook's Summary sheet.
3. **Spot check:** sampled / reviewed, errors, and the error rate per book. Books above 0.5% are highlighted, with their escalation state.
4. **Anchor and interval verses:** confirmed / 31, plus any "No" results.
5. **Versification:** candidate chapters confirmed / total.
6. **Per-book blockers:** for each unverified book, the exact reasons finalize would refuse it, using the same checks as `bk finalize`. Import the function; don't duplicate it.
7. **Rounds:** a table of round number, export date, rows and applied count.

## Acceptance criteria
- The blockers listed for a book exactly match `bk finalize`'s refusal reasons for that book.
- The numbers match a manual count on the test fixtures.

## Tests to write or update
- `test_report.py`: fixture decisions, samples and flags → the expected tables, plus the blockers-equal-finalize check.

## How to test manually
1. Run `uv run --project tools bk report`.
2. Open `reports/verification.md` → you see e.g. "Books verified: 2/66", the progress per issue type, and for Jeremiah, its open old-font rows as blockers.
