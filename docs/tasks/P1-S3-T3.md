## Why this model / review tier
- **Model:** an API integration plus a workbook write-back.
- **Review:** `auto`. It only produces **drafts** that a human must confirm and a second person review. Nothing it writes is applied without the normal workbook rules.

## Context
- There are 293 empty verses. Some are missing from the HTML entirely (e.g. Gen 31:33–55, 23 verses). Those must be **transcribed** from the scan.
- OCR is permitted by the agreement, and it's optional: typing by hand is equally valid.
- The scan PDF is at `$SCANS_DIR` (outside git).
- Use **Google Cloud Vision** `DOCUMENT_TEXT_DETECTION` (the first 1,000 pages/month are free; credentials via `gcloud auth application-default login`).
- The optional deps are installed with `uv sync --project tools --extra ocr`.

## Do this
1. **`bk ocr-gap --pdf <scan.pdf> --pages 45-46 --refs gen.31.33-55 --round 1`:**
   1. Render the pages with PyMuPDF at 300 dpi.
   2. Call Vision once per page, caching the response in `work/ocr/<page>.json` so no page is re-billed.
   3. Print the page text with line breaks, and print a cost line ("N pages sent; free tier covers 1,000/month").
2. **Draft write-back.** Write the OCR text into the "Corrected text" cell of the matching empty-verse rows in `rounds/round-<N>.xlsx`, with Notes = "OCR draft — verify against scan". **Leave Decision and Status untouched.**
   - Verse boundaries: try to split on Ge'ez/Arabic verse numbers found in the OCR text.
   - If unsure, put the whole passage into the first row and say so in Notes.
   - Replace ፡ with spaces in the draft, because the workbook convention is "no ፡".
3. A `--dry-run` option prints the drafts without writing.
4. A clear error if the `ocr` extra isn't installed.

## Acceptance criteria
- With a mocked Vision client, drafts land in the right rows; Decision and Status stay unchanged; the drafts contain no ፡.
- A second run makes no API calls for cached pages.
- Without credentials, it fails with a helpful message.

## Tests to write or update
- `test_ocr_gap.py`: mocked client, cache hit, the row targeting, ፡ → space, the verse-number splitting, dry-run.

## How to test manually
1. Run `uv sync --project tools --extra ocr`, then `uv run --project tools bk ocr-gap --pdf "$SCANS_DIR/bible.pdf" --pages <Gen 31 pages> --refs gen.31.33-55 --round 1 --dry-run` → the OCR text prints, roughly split by verse.
2. Run it without `--dry-run`, then open the workbook → the Gen 31:33–55 rows have drafts marked "OCR draft — verify against scan".
