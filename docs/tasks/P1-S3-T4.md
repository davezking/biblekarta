## Why this model / review tier
- **Model:** the rules are exact and fully specified below.
- **Review:** `opus`. This produces the frozen text that everything downstream trusts.

## Context
- Inputs: `work/applied/<book>.json` (from `bk apply`), `decisions/*.jsonl`, `rounds/samples/*.json`, the anchor-sheet results, confirmed versification rows and `scripture/books-meta.json`.
- The output shape the site reads:

  ```json
  {"book":"1ki","edition":"BSE-1954-html+scan","status":"verified","chapters":[{"n":16,"verses":[{"n":29,"t":"…","footnote":"…"}]}]}
  ```

  `n` uses the **scan** numbering. `t` holds the words separated by single spaces and **never contains ፡**.

## Do this
1. **`tools/bk/scripture_io.py`:**
   - `write_book` (UTF-8, no BOM, stable key order, 2-space indent, trailing newline).
   - `verse_hash(t) = sha256(utf8)`.
   - `validate_text(ref, t)`:
     - only Ethiopic fidel (U+1200–137F, U+1380–139F, U+2D80–2DDF, U+AB00–AB2F), ። ፣ ፤ ፥ ? and single spaces
     - **no ፡**
     - no Latin letters
     - digits only for refs in `tools/bk/data/digit_allowlist.csv`
     - no leading or trailing space, no double spaces, not empty
     - NFC (fail if NFC would change the text)
2. **`bk finalize --book 1ki [--book 2ki …] | --all`.** For each book:
   1. **Refuse** to finalize the book if any of these are open:
      - a flagged verse in this book not applied (pending or To do)
      - a spot-check row for this book not reviewed
      - an escalation open for this book
      - an anchor-sheet row in this book not "Confirmed in scan" = Yes
      - a versification candidate chapter in this book not confirmed
   2. Translate to the scan numbering via the versification map (`versify build` output).
   3. Validate every verse, and fail with a list.
   4. Check the verse counts against the **confirmed scan counts**; chapters that need no mapping use the HTML counts.
   5. Write `scripture/books/<id>.json` with `status: "verified"`.
   6. Update `checksums.json`, `verse-counts.json` and `versification.json` (only this book's keys).
   7. Write `provenance/<id>.json`: the rounds, the proofreaders and reviewers, the flags resolved by type, the spot-check sample size and error rate, the escalations, the date and the tool version.
3. **`bk verify [--book X]`:** recompute the hashes, counts and `validate_text` for every published book, and confirm that `versification.json` entries round-trip. Exit 1 with a list.
4. **Release tags** are a manual step, documented in `README.md`: after finalizing, `git tag text-v<N>` and push. The site picks it up via `scripture.lock`.

## Acceptance criteria
- Finalizing twice gives byte-identical output.
- Changing one character in a book makes `bk verify` fail and name the verse.
- A book with one unreviewed flagged verse is refused, with the reason.
- Text containing ፡ or a Latin letter fails validation.
- Job 40 is written with verses 24–32 (scan numbering) when that split is confirmed.

## Tests to write or update
- `test_finalize.py`: each refusal reason, idempotence, tamper detection, each validator rule, versification translation, and the digit allowlist.

## How to test manually
1. After round 1 is applied for 1 Kings, run `uv run --project tools bk finalize --book 1ki` → `scripture/books/1ki.json` appears with `status: verified`.
2. Run `bk verify` → OK.
3. Edit one letter, run `bk verify` → FAIL naming the verse. Revert.
4. Try `bk finalize --book jer` while its old-font rows are open → refused, with the list of open rows.
