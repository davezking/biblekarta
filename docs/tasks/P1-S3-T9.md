## Why this model / review tier
- **Model:** a small workflow change.
- **Review:** `opus`. It changes when `SCRIPTURE_TOKEN` is passed to a workflow.

## Context
- `e2e.yml` only ran on pushes to `phase-*`. Phase 1 merged into `main` directly, so the Playwright suite (including `prod-excludes-dev.spec.ts`) never ran in CI.
- P1-E2E's acceptance requires both suites to pass in CI.

## Do this
1. **`e2e.yml` triggers:**
   - `pull_request` into `main` and `phase-*`, `push` to `main` and `phase-*`, and `workflow_dispatch`.
   - Use `pull_request` only, never `pull_request_target`. Fork PRs get no secrets and fall back to the fixtures.
2. **Keep** `permissions: contents: read`, and keep the report upload on failure.
3. **Docs:** in `docs/WORKFLOW.md` and the `e2e/phase-1/README.md` footer, say where the e2e runs.

## Acceptance criteria
- A green `e2e` run on the PR and on `main` after the merge, desktop and mobile, with `prod-excludes-dev.spec.ts` passing on the runner.
- No `pull_request_target`; permissions stay read-only.

## Tests to write or update
- None new. The existing `e2e/phase-1/*` specs must pass in CI.

## How to test manually
1. Open the PR → the `e2e` check appears and passes.
2. Open the run's log → every spec passes (the production builds run on desktop only).
