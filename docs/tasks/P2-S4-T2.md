## Why this model / review tier
- **Model:** reference resolution over verse ranges, rendered through the existing strict renderer.
- **Review:** `auto`. `VerseText` and `wordSeparators()` are unchanged and keep their golden tests.

## Context
- **Scripture is sacred data (`CLAUDE.md`):**
  - Never edit, trim, normalize or re-space verse text.
  - ፡ is added only by `wordSeparators()`.
  - Render verses as plain text nodes, with `lang="am"`.
  - **Never put Bible text in this public repo,** not even in tests. Use `scripture-fixtures/` (the non-scriptural test book) in tests.
- `VerseText.tsx` (P1-S3-T7) already renders `{n, to?, t}` verses correctly. Reuse it as is.
- Verified books are served at `/data/scripture/<id>.json`, and `index.json` lists them in `scriptureBooks` (P2-S2-T3). A book not in that list shows `verse.not_ready` ("ይህ መጽሐፍ በዝግጅት ላይ ነው").
- References use the **scan's numbering**. A verse range stored as `{n: 14, to: 15}` is opened by a reference to either 14 or 15.
- FR-15: refs are shown with Amharic book names (`formatRef` in `refs.ts`). FR-16: tapping a ref shows the text in the panel without leaving the chart. FR-18: editor notes are visually separate from scripture and labelled as written by the editors. FR-19: the credit names the translation and the Society.
- **R6 (footnotes):** check the R6 row in `architecture.md` §10 and `docs/prd-changelog.md`.
  - If it's recorded as **approved**, add a "ማስታወሻ" toggle that shows the stored `footnote` under each verse.
  - Otherwise, **don't render footnotes**, and keep the `TODO(R6)`.
- The i18n keys (`verse.*`) were added by P2-S4-T1. Don't edit the i18n files.

## Do this
1. **`verse-select.ts` (pure):** `selectVerses(book, ref)` → the verse objects covering `ref`.
   - A range verse is included once if any number in it is requested.
   - It returns a `missing` list for numbers the book doesn't have.
   - It never modifies the objects.
2. **`useBook.ts`:** fetches `/data/scripture/<id>.json` once per build (an in-memory cache keyed by `scriptureVersion`). It returns `{status: 'ready' | 'not-ready' | 'loading' | 'error', book}`; the `not-ready` status comes from `scriptureBooks`, without fetching.
3. **`RefList.tsx`:** the item's refs as buttons with `formatRef`. Tapping one expands its `VerseBlock` inline, and only one is open at a time.
4. **`VerseBlock.tsx`:** the reference heading, then `<VerseText verses={selectVerses(...)}>`, then the credit line (`verse.credit`). Status rules:
   - **not-ready:** the not-ready message, and no fetch.
   - **loading:** a skeleton without text.
   - **error:** a retry button.
5. **Editor note:** in `DetailPanel`, show `note_am` in a separate box labelled `verse.editor_note`, in red ink (`.note`), never inside the verse block.
6. **Footnotes:** follow the R6 rule above. Say in the PR which branch you took and why.

## Acceptance criteria
- For a rendered ref, DOM `textContent` of each verse equals `wordSeparators(t)` from the served JSON, and no other transform is applied.
- A ref to verse 15 when the book stores `{n: 14, to: 15}` shows that range once, numbered "፲፬–፲፭".
- A ref to a book not in `scriptureBooks` shows "ይህ መጽሐፍ በዝግጅት ላይ ነው" and makes no network request.
- The editor note is outside the verse block and labelled. The credit appears under every verse block.
- No Bible text was added to the repo (`git diff` contains only code and the fixture book).

## Tests to write or update
- `verse-select.test.ts`: single verse, range, inside a range, a missing verse. Use the fixture book only.

- `VerseBlock.test.tsx` and `RefList.test.tsx`: DOM equality with `wordSeparators`, `lang="am"`, one open at a time, the credit present.
