## Why this model / review tier
- **Model:** a geometry algorithm (lane packing, width interpolation, fork curves) that has to look like Board 5 and stay deterministic.
- **Review:** `opus`. This shape is what readers see, and it is hard to change later.

## Context
- FR-1 and FR-2: one horizontal stream per polity, with forks (United Kingdom → Israel and Judah at 931 BC), endings, and width over time from editor keyframes (`width_keyframes[] {at: YearPair, width 1–5}`).
- FR-3: each reign is a segment inside its stream. FR-5: prophets sit in a ribbon above the kingdoms; approximate spans have a dashed outline.
- `Stream.kind` is `polity` | `ribbon` | `lane`, and `lane_order` sets the vertical order. The seed order is prophets 1, Sidon 2, Israel 3, United 4, Judah 5, Ethiopia 6, Aram 7, Egypt 8, Assyria 9.
- `design-reference/board5-desktop.html` is the approved look: compare your output with it.
- **Layout runs at build time** (the compiler, P2-S2-T3) for **both axes**. In the browser, zooming only scales x. FR-9: hiding a lane must move the lanes below it up without a new layout.
- Map years to x only through `timescale.ts` (P2-S2-T1).

## Do this
1. **`intervals.ts`:** `packIntervals(items: {id, x0, x1}[], gapPx)` → a row index per item (greedy, stable by `x0` then `id`). This is used for overlapping prophets in the ribbon and for overlapping events or people in a lane.
2. **`streams.ts`:** `layoutStreams({streams, reigns, people, events}, axis, cfg)` → `AxisLayout`:
   - **Lanes:** one per top-level stream, in `lane_order`, each with `{id, y0, height}`. A forked child shares its parent's lane group, so the parent's centre line and the children's bands join smoothly. Lane height is the stream's maximum width over its life, plus padding.
   - **Stream bands:** an SVG path `d` **in lane-local coordinates**, so the client can collapse a lane by shifting the lanes after it.
     - The width at x is a linear interpolation between keyframes, × `WIDTH_UNIT_PX`, and constant outside them.
     - A **fork** grows the child from the parent's centre over `FORK_YEARS`.
     - An **end** tapers over `END_YEARS`.
     - Use a smooth monotone curve (d3-shape).
     - Name the constants and justify them against the mockup in a comment.
   - **Reign segments:** `{reign_id, person_id, stream_id, x0, x1, row}`, x only. The renderer clips them to the stream path. Ribbon and lane items are packed into rows with `packIntervals`. Each segment carries `dashed: true` when its `certainty` is `approximate`.
   - **Unplaced:** per axis, the counts and ids of streams, reigns and events that `place()` couldn't place. Nothing is drawn for them.
   - **Determinism:** coordinates are rounded to 0.1 px, and the output order is stable, so tiles diff cleanly.

## Acceptance criteria
- On the scholarly axis, the seed gives Israel above and Judah below the United Kingdom, both forking at 931 BC (astronomical −930), and the ribbon on top, as in Board 5.
- A stream's band never overlaps another lane's band.
- Hiding lane *n* and shifting the later lanes up by its height gives the same picture as re-running the layout without lane *n*.
- The same input always gives byte-identical JSON.
- With the seed's TBD traditional dates, the traditional axis lists every reign as unplaced and invents no positions.

## Tests to write or update
- `intervals.test.ts`: overlaps, touching intervals, stability.
- `streams.test.ts`: keyframe interpolation; the fork start point equals the parent's centre; taper at ends; no lane overlap; the lane-collapse equivalence; determinism; seed snapshot (scholarly); traditional axis all unplaced.

## How to test manually
1. Run `pnpm test -- streams intervals` → all pass.
2. Render the seed layout as a static SVG (a small `tsx` script, or the snapshot test's output file) and open it next to `design-reference/board5-desktop.html` → the same lane order and the fork at 931.
