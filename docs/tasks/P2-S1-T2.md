## Why this model / review tier
- **Model:** porting an existing SVG pattern into a component.
- **Review:** `auto`.

## Context
- DR-5: interlaced harag bands (yellow ground, red and green strands, black outlines) frame the page title and the top and bottom of the chart.
- `design-reference/board5-desktop.html` has four of them, as SVG `<pattern>`s `hg1`…`hg4` (44 px wide; 26, 18, 16 and 16 px tall). That drawing is approved: copy its geometry, don't redraw it.
- Colours come from `src/lib/core/tokens.ts` (`harag.*`, `ink.black`) from P2-S1-T1.
- The band is used both in Astro pages (around the title) and inside the React chart island.

## Do this
1. **`src/components/ornament/HaragBand.tsx`:** props `{height: 16 | 18 | 26; className?}`.
   - It renders a full-width `<svg aria-hidden="true">` filled with the pattern for that height, ported from `hg1`…`hg4`.
   - Use the token colours, not literal hex values.
   - Make each pattern id unique with React `useId()`, so several bands on one page don't collide.
   - No JS behaviour, so it works server-rendered in Astro without hydration.
2. **`src/components/ornament/TitleCartouche.tsx`:** the centred title block from the mockup: harag above and below, and the title in red Abyssinica (`.rubric`), with no bold. Props: `{title: string; subtitle?: string}`.

## Acceptance criteria
- At each height, the band's pattern geometry matches the mockup's (same paths and sizes, token colours).
- Two bands on one page have different pattern ids.
- Each band root is `aria-hidden`, and the cartouche title is real text, not inside the SVG.

## Tests to write or update
- `HaragBand.test.tsx` (happy-dom, as in `VerseText.test.tsx`): the right pattern per height, unique ids across two instances, `aria-hidden`, and token colours in the output.

## How to test manually
1. Render a `<HaragBand height={26} />` on any dev page → it matches the band at the top of `design-reference/board5-desktop.html`.
2. Zoom the browser to 300% → the band stays crisp and seamless.
