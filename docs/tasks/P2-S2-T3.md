## Why this model / review tier
- **Model:** wiring existing pure modules into a build step with clear contracts.
- **Review:** `auto`. The contract types and budget checks are tested.

## Context
- Architecture §5: the static data contracts.
  - `/data/index.json` (≤ 30 KB gz): eras, stream meta, anchors, the timescale config, minimap data, build id and scripture version.
  - `/data/tiles/<era>.json` (≤ 100 KB gz each): stream paths (both axes), reigns, people and events.
  - Relationships, adjacency and stubs come in Phase 3 (P3-S2-T1). Leave them out of the tiles now.
- `src/build/validate-content.ts` already validates `content/` and overlays `seed/` (`withSeed`). `copy-scripture.ts` shows how an Astro integration writes into `public/data/` at build and dev time. Follow the same pattern.
- `CLAUDE.md`: the MVP shows only `canon: "shared"`. `seed/` must never reach a production build: overlay it only when `BK_SEED=1`.
- Layout comes from `layoutStreams()` (P2-S2-T2) and `buildTimescaleConfig()` / `place()` (P2-S2-T1).

## Do this
1. **`src/lib/core/datafiles.ts`:** the TypeScript types for `IndexFile` and `TileFile`, shared by the compiler and the browser. This is the contract; version it with `DATA_VERSION = 1`.
2. **`compile-data.ts`:** `compileData({contentDir, seedDir?, outDir, env})`:
   - Validate first, and fail the build on any validation error.
   - Overlay `seed/` only when `BK_SEED=1`. Keep only `canon: "shared"` items.
   - Build the timescale config, then lay out both axes.
   - Write `index.json` and one tile per **live** era (an item belongs to every era its placed span intersects; streams go to every era they cross).
   - **Tiles carry what the panel needs** (names, slugs, `figure_kind`/`figure_tone`, importance, `DateValue`s, refs, notes), so Sprint 4 needs no extra fetch apart from scripture.
   - Tiles also carry the `sources` and `anchors` that their dates cite, so the panel can explain how each date is known.
   - **Index:** the eras (with `status`, so "coming soon" eras appear in the minimap), streams (id, names, kind, colour, lane), anchors, `scriptureBooks` (the ids of the verified books this build publishes to `/data/scripture/`, from `loadVerifiedBooks()` / the same source as `copy-scripture.ts`), per-era unplaced counts for each axis, `buildId` (the git SHA, or a timestamp if git isn't available), `scriptureVersion` (the contents of `scripture.lock`) and `DATA_VERSION`.
   - **Budgets:** gzip each file. Warn at 80% of its budget, fail above 100%. Print a one-line summary per file.
3. **Integration:** run it from an Astro integration (`astro:build:start` and dev-server start) registered in `astro.config.mjs`, writing to `public/data/` (already git-ignored).
4. **Script:** `pnpm compile:data`, to run it on its own.

## Acceptance criteria
- `BK_SEED=1 pnpm build` writes `index.json` and `tiles/divided-kingdom.json`, both within budget.
- A production build (no `BK_SEED`) with an empty `content/` writes an index with zero live eras and no tiles, and contains no `fixture: true` data.
- Non-`shared` items never appear in the output.
- The output is deterministic: two builds of the same input give identical files, apart from `buildId`.

## Tests to write or update
- `compile-data.test.ts` with small fixtures in `src/build/__fixtures__/compile/`: seed overlay on/off, the canon filter, era membership, unplaced counts, the budget warn/fail thresholds (with a tiny injected budget), determinism, and a type-check of the output against `datafiles.ts`.

## How to test manually
1. Run `BK_SEED=1 pnpm compile:data` → the summary shows the index and the divided-kingdom tile with their gzip sizes under budget.
2. Open `public/data/tiles/divided-kingdom.json` → Ahab is there with his scholarly reign geometry, and appears under unplaced for the traditional axis.
