## Why this model / review tier
- **Model:** parsing and application logic with clear rules.
- **Review:** `opus`. This writes corrected Bible text, splits merged verses and enforces two-person review.

## Context
- The proofreaders return `rounds/round-<N>.xlsx` with the yellow columns filled (see P1-S2-T6).
- **Rules:**
  - The scan always wins.
  - "Corrected text" = the words exactly as printed, separated by single spaces, **without ፡**.
  - Footnotes go in Notes.
  - **A second person reviews every Fix, Transcribed, Split or Moved row and sets Status = Reviewed.**
- The cleaned text is in `work/clean/`. The versification map tools are in `versify_core`.

## Do this
1. **`workbook_import.read(path) → rows`** for all four sheets. Validate each row and **report** (never silently skip):
   - Decision is required when Status ≠ "To do".
   - Fix, Transcribed, Split and Moved need Corrected text, a Proofreader, a Reviewer **different from the Proofreader**, and Status = Reviewed. Otherwise the row is "pending" and not applied.
   - Keep and Delete marker need a Proofreader (a reviewer is optional for Keep, required for Delete marker).
   - Corrected text must contain **no ፡**, no Latin letters, no double spaces, and no leading or trailing space. Digits are allowed only if the ref is in `tools/bk/data/digit_allowlist.csv` (create it, seeded with `1sa.13.21`).
2. **`apply_core.apply(clean, rows, vmap)`** produces `work/applied/<book>.json`:
   - **Fix / Transcribed:** replace `t` with the corrected text at the **scan reference** (default: the same as HTML).
   - **Keep:** no change.
   - **Delete marker:** accept the cleaner's stray-marker removal; if it was only suggested, apply it.
   - **Split:** the HTML verse becomes several scan verses. The proofreader enters one row per resulting scan verse, with the same HTML reference and different scan references. Record the mapping for the versification map.
   - **Moved:** text found in a neighboring verse. Apply both sides (the source verse's corrected text is entered on its own row).
   - Spot-check rows with Decision = Fix count as errors for `bk sample escalate`.
   - Anchor sheet: record `Scan reading` and `Confirmed in scan?`. A "No" creates a blocking issue for finalize.
   - Versification sheet: confirmed rows go to `bk versify build`.
3. **`bk apply --round N rounds/round-N.xlsx`** writes `decisions/round-N.jsonl` (one line per applied row: `{ref_html, ref_scan, decision, final_text, proofreader, reviewer, status, round}`) and `work/applied/`. It prints applied, pending and rejected counts, with the reason for each rejection.
4. **Idempotent:** re-importing the same workbook changes nothing. A later round overrides an earlier decision for the same scan reference, and logs that it did.

## Acceptance criteria
- A filled fixture workbook (create `tools/tests/fixtures/round-filled.xlsx` from the oracle with ~12 filled rows covering every decision type) applies with the expected results.
- A row where Reviewer = Proofreader is reported as pending and **not** applied.
- Corrected text containing ፡ is rejected with a clear message ("ፊደል ብቻ — ፡ አይጻፍ").
- The Job 40:24 split yields scan verses 24–32.

## Tests to write or update
- `test_apply.py`: every decision type, review enforcement, the text validation errors, the split mapping, idempotence, and later-round precedence.

## How to test manually
1. Fill 3 rows of `rounds/round-1.xlsx`: a Fix reviewed by a second name, a Fix with no reviewer, and a Keep.
2. Run `uv run --project tools bk apply --round 1 rounds/round-1.xlsx` → "applied 2 · pending 1 (no reviewer)".
3. Open `decisions/round-1.jsonl` → it has 2 lines.
