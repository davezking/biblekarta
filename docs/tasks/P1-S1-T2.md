## Why this model / review tier
- **Model:** core contract work with cross-reference rules; it needs care, but the design is fully specified.
- **Review:** `auto`. It's well covered by tests, and the phase review checks it for data-model drift.

## Context
Content is JSON, one file per entry, in `content/<collection>/<id>.json` (and `seed/<collection>/` on previews). These schemas are the single source of truth for the CMS, the compiler and the tests. The entity list is in `architecture.md` §4; the fields are listed below.

## Do this
1. In `src/lib/core/schema.ts`, export these Zod schemas and their inferred types:
   - **`YearPair`** `{traditional?: int, scholarly?: int}`, with at least one present.
   - **`DateValue`** `{start?: int, end?: int, certainty: 'exact'|'approximate'|'range'|'disputed'|'tradition_only', method: 'anchor'|'derived'|'traditional'|'relative', source_id?, anchor_id?, anchor_value_used?: int, derivation_refs?: ScriptureRef[], relative_text_am?}`. Refinements:
     - `derived` ⇒ `anchor_id` and `anchor_value_used`
     - `traditional` ⇒ `source_id`
     - `relative` ⇒ `relative_text_am` and no `start`
     - otherwise ⇒ `start`
   - **`ScriptureRef`** `{book_id, chapter: int≥1, verse_start: int≥1, verse_end?: int}`, with `verse_end ≥ verse_start`.
   - **`Canon`** `'shared'|'ethiopian_81'`. Every entity gets `canon` (default `shared`) and an optional `fixture: boolean`.
   - **`Stream`:** id, slug, name_am, name_en, kind `polity|ribbon|lane`, fill_color (`#RRGGBB`), parent_stream_id?, fork?: YearPair, end?: YearPair, width_keyframes: `{at: YearPair, width: 1..5}[]`, lane_order: int.
   - **`Era`:** id, slug, name_am, name_en, start?: YearPair, end?: YearPair (both required when `status: 'live'`), certainty `anchored|approximate|disputed|tradition_only`, status `live|coming_soon`, order, gap?: boolean, lod?: record, minimap_weight?: number.
   - **`Person`:** id, slug, name_am, name_en, aliases: string[], figure_kind `king|queen|prophet|christ|apostle|other`, figure_tone?, importance 1..5, stream_id, birth_traditional?, birth_scholarly?, death_traditional?, death_scholarly? (DateValue), note_am?, note_en?, refs: ScriptureRef[].
   - **`Reign`:** id, person_id, stream_id, start_traditional?, start_scholarly?, end_traditional?, end_scholarly?, coregency_flag: boolean.
   - **`Event`:** id, slug, title_am, title_en, summary_am?, summary_en?, stream_id?, type `point|span`, date_traditional?, date_scholarly?, importance 1..5, refs, note_am?, note_en?.
   - **`Relationship`:** id, person_a_id, person_b_id, type `parent|married|succeeded|allied|opposed|war|prophesied_to`, label_am, date?, refs.
   - **`Anchor`:** id, label_am, label_en, date `{start: int, end?: int}`, external_source, confidence `high|medium|low`, notes?.
   - **`Book`:** id, name_am (scan name), name_en, html_name_am?, abbr_am?, testament `ot|nt`, order_66 (scan order), html_order?, order_81?, period_setting?: YearPair. Books are **not** a content collection. They're loaded from `$SCRIPTURE_DIR/books-meta.json`, falling back to `scripture-fixtures/books-meta.json` (created by P1-S1-T1).
   - **`Source`:** id, citation, kind `tradition|scholarly`.
   - Also export a `COLLECTIONS` map from folder name to schema (books excluded), plus `loadBooks()`.
2. `src/build/validate-content.ts`, run as `pnpm validate [--dir content] [--with-seed] [--format text|json]`:
   1. Load every collection and parse it.
   2. Check referential integrity:
      - all `*_id` values resolve
      - `person_a_id ≠ person_b_id`
      - a Reign's stream equals its person's stream unless `coregency_flag` is set
      - a derived date's anchor exists
      - every slug is unique per collection
   3. Print the errors grouped by file (or as JSON) and exit 1 if there are any.
   4. Leave a clearly marked `checkVerseRanges()` hook that does nothing yet.
   5. With `--with-seed`, merge `seed/` over `content/` (content wins on an id clash).

## Acceptance criteria
- Every DateValue refinement rejects bad input with a readable message naming the field.
- A dangling `stream_id` is reported with the file path and the field path.
- `pnpm validate` exits 0 on the empty `content/` folder.

## Tests to write or update
- `schema.test.ts`: one valid and one invalid example per entity; each DateValue rule.
- `validate-content.test.ts`: fixture folders under `src/build/__fixtures__/validate/` (good, a dangling ref, a duplicate slug, an anchor-less derived date).

## How to test manually
1. Run `pnpm validate` → it prints "0 errors".
2. Copy `src/build/__fixtures__/validate/dangling/` into `content/` and run `pnpm validate` → it shows a clear error naming the file and field, with exit code 1. Delete the copy afterwards.
