## Why this model / review tier
- **Model:** small, but the contrast maths and the "which text sits on which fill" table need care.
- **Review:** `auto`. The tests pin every colour pair.

## Context
- `src/styles/base.css` has only three Phase 1 tokens (`--ink`, `--ink-red`, `--vellum`) and the `.vellum`, `.ms` and `.ms-red` classes. `src/styles/fonts.css` defines `--font-manuscript` and `--font-ui`.
- `CLAUDE.md` says the tokens live in `src/lib/core/tokens.ts` / `src/styles/tokens.css`. Neither exists yet.
- The colours are fixed by the PRD and must not be changed:
  - **Inks:** black #1E1712, red #8A1A12. **Vellum** #E9D8B4.
  - **Harag:** strand red #A52119, green #3F6B3A, yellow ground #E2B54F.
  - **Stream pigments (DR-6):** United Kingdom #9DB28A, Israel #E2B54F, Judah #DE9479, Ethiopia #8FB0C4, Egypt #DCC08A, Assyria #93A487, Aram #B7B9C9, Sidon #D9C39A, Prophets #D8DFC0 / #B4C795.
  - **Figure tones** (`design-reference/figure.html`): #C99A3B, #8E2B1F, #3E6B4C, #6B5E52. The figure also uses its own fixed colours (skin, eyes, crown); copy them from that file.
- DR-3: titles, stream names, notes and highlights are red ink; body text is black; no bold in manuscript text. DR-13: text on a pigment fill ≥ 4.5:1, and stream colours that must be told apart differ in lightness, not only in hue.
- The other Sprint 1 tasks (harag, figure, UI) only *read* these tokens.

## Do this
1. **`src/lib/core/tokens.ts`:** typed `as const` objects for:
   - `ink`, `harag`, `vellum`, `pigment` (one key per stream id in `seed/streams/`, plus `prophetsDark` for #B4C795), and `figure` (tones and fixed parts);
   - spacing, radii, z-index layers (chart, toolbar, panel, sheet, tooltip);
   - motion durations, `breakpoint.desktop = 1024`, `touchTarget = 44`.
2. **`TEXT_ON_FILL`:** in the same file, a table of every text-colour × background pair the design actually uses: black ink on each pigment and on vellum; red ink on vellum and on the fills where red labels appear in `design-reference/board5-desktop.html`; UI text on vellum.
   - If a pair the mockup uses fails 4.5:1, **don't change the PRD colour**. Switch that label to black ink, record it in the table with a comment, and list it in the PR.
3. **`src/lib/core/contrast.ts`:** pure WCAG 2.x `relativeLuminance(hex)` and `contrastRatio(a, b)`, plus `lightness(hex)` (CIELAB L*).
4. **`src/styles/tokens.css`:** the same values as CSS custom properties on `:root` (`--ink`, `--ink-red`, `--vellum`, `--harag-red`, `--pigment-israel`, …).
   - Move the three Phase 1 tokens out of `base.css` into it, and import it from `Base.astro` before `base.css`.
   - Keep the existing names so nothing else breaks.
5. **Rubrication and vellum in `base.css`:**
   - add `.rubric` (red ink for titles and stream names) and `.note` (red ink, for editor notes);
   - make `.vellum` read its colours from the tokens;
   - add a `@media (prefers-reduced-motion: reduce)` rule that zeroes the motion tokens.

## Acceptance criteria
- Every colour listed in Context appears in `tokens.ts` with exactly that hex value.
- Every pair in `TEXT_ON_FILL` has a contrast ratio ≥ 4.5:1.
- The chosen lightness-difference threshold is a named constant with a comment, and these pairs pass it: Israel vs Judah, United vs Israel, United vs Judah, and each neighbour lane vs the one below it in lane order.
- `tokens.css` and `tokens.ts` never drift: a test parses the CSS and compares every value.
- `/dev/scripture/` and `/dev/playground` look the same as before.

## Tests to write or update
- `contrast.test.ts`: known WCAG reference values (black/white = 21, #777777 on white ≈ 4.48), plus symmetry.
- `tokens.test.ts`: every `TEXT_ON_FILL` pair ≥ 4.5; the lightness pairs; CSS ↔ TS equality; the DR-6 hex values pinned.

## How to test manually
1. Run `pnpm test -- tokens contrast` → all pass. The PR lists any label switched to black ink.
2. Run `BK_SEED=1 pnpm dev` and open `/dev/scripture/` → the same vellum page and red headings as before.
