## Why this model / review tier
- **Model:** classification rules with a precise test oracle.
- **Review:** `auto`. The oracle test proves it reproduces the agreed flags.

## Context
- Inputs: `work/raw/` and `work/clean/`, plus `cleaning-log.jsonl`.
- **Test oracle:** `tests/fixtures/flagged-verses-v1.xlsx`, sheet "Flagged verses", 436 rows. Its columns are Book no., Book (English), Chapter (HTML), Verse (HTML), **Primary issue** and **All issues**.
- The issue types and their counts (primary issue): Empty verse 293, Stray marker 52, Old-font junk 50, Footnote mixed into verse 23, Merged verses 9, Digits in text 7, Footnote replaced verse 1, Typo spotted 1. The PRD's "24 footnote" = 23 mixed + 1 replaced.
- "Typo spotted" comes from human review (e.g. Jer 52:12), not detection.

## Do this
1. **`tools/bk/flag_core.py`:** `flag_verse(raw, clean, ops) → [issue]`, with these detectors:
   - **Empty verse:** `t` is empty after cleaning.
   - **Old-font junk:** Latin letters remain in `t`.
   - **Footnote mixed into verse:** `extract_footnote` fired.
   - **Footnote replaced verse:** the ‖ pattern.
   - **Merged verses:** inline `\d+፤` or `[\d+]`.
   - **Stray marker:** `remove_stray_markers` fired. It's still flagged, so a human confirms.
   - **Digits in text:** any ASCII digit in `t`.
   - **Typo spotted:** listed in `tools/bk/data/manual_flags.csv` (`ref_html, issue, hint`), seeded with the oracle's typo row.
2. **Primary issue:** use a fixed precedence that reproduces the oracle. Derive it by comparing against the oracle, then document it.
3. Each flag carries the **Hint** text, matching the oracle's wording style (e.g. "Stray footnote marker (a / v). Remove.").
4. **`bk flag`:** writes `work/flags.json` (`[{ref_html, book, chapter, verse, primary, all, hint, html_text}]`, where `html_text` is the raw text, as in the workbook's "HTML text (as received)") and prints counts by type.

## Acceptance criteria
- **On the real data, the set of `(book, chapter, verse, primary issue)` equals the oracle's 436 rows exactly.** A test reads the oracle xlsx with openpyxl. It's skipped with a clear message if `source/am_new.zip` is missing (e.g. in a fork), but runs in this repo's CI.
- The counts by type match the oracle.

## Tests to write or update
- `test_flag.py`: a unit test per detector on literal examples; the oracle-equality test.

## How to test manually
1. Run `uv run --project tools bk flag` → it prints 436 flags, with the same breakdown as the workbook's Summary sheet.
2. Pick 3 rows from the oracle workbook → they appear in `work/flags.json` with the same primary issue.
