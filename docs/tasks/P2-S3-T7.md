## Why this model / review tier
- **Model:** profiling and fixing jank across the whole chart needs judgement about where the time goes.
- **Review:** `opus`. It touches every chart file, and PRD risk #9 (SVG performance on cheap phones) is decided here for Phase 2.

## Context
- The targets (architecture §1 and §9):
  - 60 fps pan/zoom on cheap Android phones;
  - **p95 frame ≤ 20 ms at 4× CPU throttle**;
  - initial JS ≤ 250 KB gz, chart island ≤ 180 KB gz;
  - LCP ≤ 3 s on 3G.
- If SVG can't meet the target, the fallback is Canvas for the stream layer only (PRD risk #9). That decision belongs to P5-S2-T1 with dense data; here, measure and fix within SVG, and record the numbers.
- The Board 5 seed is small. A **stress seed** is needed to see real load. **It must be obviously synthetic** (names like "Stress 001", `fixture: true`), generated into a temp directory at test time, and **never written to `seed/` or `content/`**. It isn't biblical data, so it can't break the "never invent biblical data" rule.
- `compileData()` (P2-S2-T3) accepts a `seedDir`.

## Do this
1. **`scripts/stress-seed.mjs`:** generates about 10× the Board 5 density for one era into a temp dir: 40 streams, 600 reigns, 300 events, 60 prophets, all valid against the schemas, with `fixture: true` and synthetic names.
2. **`e2e/perf/`:** a Playwright spec (Chromium, desktop and the Pixel 7 project).
   - It builds with the stress seed, sets CDP `Emulation.setCPUThrottlingRate` to 4, and runs a scripted wheel-zoom, pan and pinch sequence while recording frame times (`requestAnimationFrame` deltas or the CDP tracing timeline).
   - It asserts p95 ≤ 20 ms. It also checks the JS budgets from the build output, and LCP under Fast 3G emulation.
   - Make it a separate `pnpm perf` script, not part of `pnpm e2e`, so the PR suite stays fast. CI runs it in the `e2e` workflow only on pushes to `phase-*`.
3. **Fix what the profile shows,** inside `src/components/chart/` and `src/lib/layout/`. Typical suspects: label measurement, layout thrash, too many DOM nodes outside the viewport, figures not using the sprite. Keep the "no React commit during gestures" tests green.
4. **Record** the before/after numbers in `e2e/perf/README.md`.

## Acceptance criteria
- With the stress seed at 4× CPU throttle, p95 frame time ≤ 20 ms during zoom and pan, on both projects.
- Initial JS ≤ 250 KB gz, and the chart island ≤ 180 KB gz.
- LCP ≤ 3 s under Fast 3G emulation on the seeded preview build.
- No stress data appears in `seed/`, `content/` or any build without the perf flag.
- All the existing chart tests still pass.

## Tests to write or update
- `e2e/perf/chart-perf.spec.ts` and its README (the method and the numbers).
- Unit tests for any pure helper added during the fixes.

## How to test manually
1. Run `pnpm perf` → the report prints the p95 frame times and the JS sizes, all within budget.
2. On a real low-end Android phone, open the seeded preview and pinch-zoom quickly → no visible jank.
