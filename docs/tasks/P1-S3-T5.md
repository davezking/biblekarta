## Why this model / review tier
- **Model:** build plumbing with a scoped secret.
- **Review:** `opus`. This is the path by which Bible text enters the public site, and it handles a private-repo token in a public repo's build.

## Context
- The private repo `biblekarta-scripture` publishes `scripture/books/*.json`, `checksums.json`, `verse-counts.json`, `versification.json` and `books-meta.json` (format in P1-S3-T4), and is tagged `text-v<N>`.
- The public site has `scripture.lock` (currently `none`), `scripture-fixtures/` (a test book only) and a stub `scripts/fetch-scripture.sh`.
- `SCRIPTURE_TOKEN` is a fine-grained PAT with Contents: read on `biblekarta-scripture` only. It's set in the Cloudflare env and in the Actions secrets. It's never available to fork PRs.

## Do this
1. **`scripts/fetch-scripture.sh`:**
   - If `SCRIPTURE_TOKEN` is set and `scripture.lock` holds a SHA, do a shallow clone of `biblekarta-scripture` into `.scripture/` (`git init`, `git fetch --depth 1 https://x-access-token:$SCRIPTURE_TOKEN@github.com/<owner>/biblekarta-scripture <sha>`, `git checkout FETCH_HEAD`). **Never echo the token.** Use `set +x` and pass it via `GIT_ASKPASS` or an env-based credential helper rather than the URL if possible.
   - Export `SCRIPTURE_DIR=.scripture/scripture` and `BK_SCRIPTURE=real`.
   - Otherwise, export `SCRIPTURE_DIR=scripture-fixtures` and `BK_SCRIPTURE=fixtures`, and print a notice.
   - Write the values to `.scripture.env` so `pnpm build` can read them.
2. **`scripture.lock`:** set it to the SHA of the current `text-v1` tag (the owner provides it; document `git -C ../biblekarta-scripture rev-parse text-v1`).
3. **`src/build/verify-scripture.ts`:** a TS port of `bk verify` (hashes, counts, allowed characters, **no ፡ in stored text**). It runs against `SCRIPTURE_DIR` and exits 1 with the mismatches.
4. **`src/build/copy-scripture.ts`:** from an Astro integration hook at build start, copy the `books/*.json` files whose `status` is `verified` to `public/data/scripture/`, **byte-for-byte** (`fs.copyFile`), then re-hash the copies against `checksums.json`. Also export the scripture version (the lock SHA, or `fixtures`) into `index.json` later.
5. **`src/lib/core/books.ts`:** load `$SCRIPTURE_DIR/books-meta.json`. Add a test that the fixture `books-meta.json` ids, scan names and order equal the real ones whenever `BK_SCRIPTURE=real`.
6. **Production guard:** a production build (no `BK_SEED`) **fails** if `BK_SCRIPTURE=fixtures`, so the live site can never ship the test book. The only exception is `BK_ALLOW_FIXTURE_SCRIPTURE=1`, which CI sets so fork PRs can still run the production-build check (see `ci.yml`). It must never be set in Cloudflare; document this in `docs/deploy.md`.

## Acceptance criteria
- With no token, the build passes using fixtures and logs that it did. A production build with no token fails.
- With a token and lock, `.scripture/` holds exactly the locked commit, `verify:scripture` passes, and the copies are byte-identical (`Buffer.equals`).
- The token never appears in the logs (a test runs the script with a dummy token and greps the output).

## Tests to write or update
- `verify-scripture.test.ts`: good and tampered fixture books, and a book containing ፡ (fails).
- `copy-scripture.test.ts`: byte identity, and that unverified books are skipped.
- Shell test (bats, or a Vitest `child_process` test): the fallback path, the production guard, and that the token isn't printed.

## How to test manually
1. Without a token: `scripts/fetch-scripture.sh && pnpm build` → "using fixtures" and the build passes.
2. With `SCRIPTURE_TOKEN=$(gh auth token)` (locally only) and the lock set: the same command → "using scripture <sha>", and `dist/data/scripture/1ki.json` exists.
3. On the task's Cloudflare preview, open `/data/scripture/1ki.json` → the verified text, with no ፡ in the raw JSON.
