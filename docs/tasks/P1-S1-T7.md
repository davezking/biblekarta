## Why this model / review tier
- **Model:** a simple UI over functions that already exist.
- **Review:** `auto`.

## Context
The utilities `geez.ts`, `normalize.ts` and `dates.ts` (in `src/lib/core/`) are invisible to a person. This page makes them checkable on any preview URL. Every `/dev/*` page must be **excluded from production builds** (previews set `BK_SEED=1`; production doesn't).

## Do this
1. **Translator.** Create `src/lib/i18n.ts`, a tiny `t(key, vars?)` factory for `am` and `en` built from `src/i18n/*.json`.
2. **Dev index.** `src/pages/dev/index.astro`: a list of dev pages (for now, just Playground).
3. **Playground.** `src/pages/dev/playground.astro` mounts `Playground.tsx` (`client:load`) with three cards:
   - **Ge'ez:** a number input → `toGeez`, and a text input → `fromGeez` (shows the error message on invalid input).
   - **Dates:** an astronomical-year input and an AA input → both formatters, in am and en, for each certainty (a select).
   - **Normalizer:** a text input → the `normalizeAm` key.
4. **Exclude `/dev/` from production.** In `astro.config.mjs`, when `process.env.BK_SEED !== '1'`, exclude `src/pages/dev/**` with an integration that removes the routes, or with `getStaticPaths` guards. Pick the simplest reliable way and document it in a comment. A `devOnly` helper may live in `src/middleware/devOnly.ts`.

## Acceptance criteria
- `BK_SEED=1 pnpm build` includes `/dev/playground/`. `pnpm build` (no env) contains no `dev/` output.
- The playground shows 950 → ፱፻፶, −852 → "853 ዓ.ዓ.", and ሐዋርያት → ሀዋርያት.

## Tests to write or update
- `e2e/dev-playground.spec.ts`: the three examples above.
- A build test (Vitest or a small node script in CI) asserting that `dist/dev` is absent from a production build.

## How to test manually
1. Open `<task preview URL>/dev/playground/`.
2. Type 1990 in the Ge'ez card → you see ፲፱፻፺. Type ሠራ in the normalizer → you see ሰራ.
