## Why this model / review tier
- **Model:** caching, cancellation and windowing logic, with tests.
- **Review:** `auto`.

## Context
- NFR (architecture §9): load the tiles within ±1 era of the viewport. Tiles are `/data/tiles/<era>.json` (≤ 100 KB gz each), described by `/data/index.json` (types in `src/lib/core/datafiles.ts`).
- Phase 2 has one live era, but the loader must handle many: Phase 5 covers creation → AD 100.
- P2-S2-T4 created `src/components/chart/data/useChartData.ts`, which simply fetches the index and the single live tile. Replace its internals and keep its return type, so no layer changes.
- Offline caching (service worker) is Phase 4. This task is about in-memory loading and windowing.
- The chart rule applies: nothing here may cause a React commit during a gesture. Read the committed viewport, not the live one.

## Do this
1. **`tiles.ts`:** a tile cache keyed by `buildId` + era slug.
   - It de-duplicates in-flight fetches and aborts requests for eras that leave the ±1 window before they arrive (`AbortController`).
   - It keeps at most N tiles in memory (LRU, N = 5).
2. **`window.ts` (pure):** `erasInWindow(index, viewportYears, axis)` → the live eras intersecting the viewport, plus one era either side.
3. **`visible.ts` (pure):** `visibleItems(tileItems, [x0, x1], marginPx)` → the items whose x-span intersects the viewport plus a margin of one screen width. Layers render only these.
4. **`useChartData`:** at each committed viewport, decide which eras to load, merge the loaded tiles into one view model (stable order, de-duplicated by id: a stream spanning two eras appears once), and expose `{index, view, status}`.
   - `status` is `loading` | `ready` | `error`.
   - Don't add any UI strings. An error shows the existing chart frame with nothing drawn, and logs to the console.

## Acceptance criteria
- Panning across era boundaries loads the next era's tile before it is on screen (at the ±1 window), and drops tiles beyond the LRU limit.
- A tile request for an era that leaves the window is aborted.
- Merging two tiles never duplicates an item.
- Layers receive only the items intersecting the viewport plus a margin.
- No React commits during a simulated gesture (same Profiler check as P2-S2-T4).

## Tests to write or update
- `tiles.test.ts`: de-dup, abort, LRU eviction, buildId keying (a new build never reuses old tiles).
- `window.test.ts` and `visible.test.ts`: boundaries and margins.
- A `useChartData` test with a three-era fixture index and mocked fetch.

## How to test manually
1. Open the seeded preview with DevTools → Network → one `index.json` and one `divided-kingdom.json` request, each fetched once.
2. Pan to the far edge and back → no repeated tile requests.
